# 판정 심문 Agent 평가 프로토콜 (Agent 코드 작성 전 봉인, 2026-11-02)

**질문:** 코드가 전제를 FALSE로 새로 판정했을 때, Agent가 데이터 착시와 실제 깨짐을 가려내는가. 코드 판정은 어떤 경우에도 바꾸지 않고 이의만 기록한다.

**평가 단위:** 코드가 새로 FALSE로 판정한 전제 1개.
- 개발(튜닝 가능): agent-value 개발 표본에서 나온 units-dev(14개), v4 봉인 시즌 4개 전제 사례
- 잠금 평가(튜닝 금지): units-test(16개), units-new(시드 20261102, 회사당 1개, 30개)
- 추가 전향 평가: v5 봉인 후 새 깨짐. 원문 정답을 Agent 실행 전에 기록

**정답:** 결과를 보지 않은 GPT-6.1이 SEC 원문으로 전제 참거짓을 판정. REAL=전제가 원문상 거짓, ARTIFACT=원문상 참. AI 정답이므로 사람 교차 표본을 별도 표시한다.

**비교군:** A 코드(항상 REAL), B LLM 1회(같은 fact 자료 묶음), C Agent(도구 선택, 최대 3라운드, LLM 5회 이내). B와 C는 같은 모델. 출력은 REAL / ARTIFACT / UNSURE.

**지표(잠금 평가, 사전 고정):**
1. 위험 오류: 실제 깨짐을 ARTIFACT로 판단한 수 (낮을수록 좋음, 가장 중요)
2. 착시 포착: 착시를 ARTIFACT로 판단한 수
3. 보류율: UNSURE 비율
4. 근거 검사 통과율: C의 인용이 도구 출력에 실제로 있는 비율. 미통과 판단은 UNSURE로 처리

**판정 규칙:** C가 B보다 위험 오류가 많으면 Agent 패배. 위험 오류가 같거나 적고 착시 포착이 많으면 Agent 우세. 그 외는 "차이 확인 못함". A 대비 위험 오류가 1건이라도 있으면 그 수를 함께 보고한다. 표본이 작으므로 통계적 일반화는 하지 않는다.

**절차:** 잠금 평가 전에 코드와 프롬프트의 해시를 공개 커밋한다. 잠금 평가는 1회만 실행하고 결과와 무관하게 공개한다. 정답 오류가 드러나면 수정 전후를 모두 보고한다.
